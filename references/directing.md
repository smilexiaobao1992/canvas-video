# 分镜、镜头和节奏

这里的工具解决一类问题：画面每一张都没毛病，连起来却像翻幻灯片。常见的原因是一幕只有一个构图、一停就是八九秒，画面只占中间一块，镜头不动。下面的函数让“切镜头、给特写、动镜头、铺满画面”变成几行代码的事。它们是工具，不是要求：怎么用、用多少、用不用，由这部片子决定。一部安静的片子长时间停在一个画面上、大片留白，只要是有意为之，就没有问题。

## 一幕里切几个镜头：`shots()`

一个场景（script.json 里的一个 `id`）可以拆成几个镜头，每个镜头有自己的画面和镜头运动，在台词的某个词上切换：

```js
const SCENES = {
  bell: shots((S) => [
    { // 第一个镜头从场景开头开始
      cam: (lt, S, sh) => camMove({ x: 540, y: 1000, z: 1 }, { x: 540, y: 1180, z: 1.6 }, sh.p),
      draw(lt, S, t, sh) { /* 全景 */ },
    },
    { at: S.word(0, '吕后') - 0.4,          // 念到“吕后”前 0.4 秒切过来
      draw(lt, S, t, sh) { /* 特写 */ } },   // 不写 cam：这个镜头自己缓慢推近
    { at: S.L(1).s, transition: 'fade', draw(lt, S, t, sh) { /* … */ } },
  ]),
};
```

- `at`：这个镜头开始的时刻（场景内秒数），一般挂在 `S.word` / `S.L` 上；镜头按时间顺序写，持续到下一个镜头开始。
- `draw(lt, S, t, sh)`：`lt` 仍然是**场景**的时间，所以 `S.word`、`S.L` 照常用。`sh = { index, start, dur, t, p }`，`sh.t` 是进入这个镜头后的秒数，`sh.p` 是镜头内进度 0..1。
- `cam(lt, S, sh)`：返回 `{ x, y, z }`，三项都可以省。不写时先找 `CAMS[场景 id]`，再没有就是镜头内 3.5% 缓慢推近。
- 镜头之间默认硬切。`transition` 可以写任何场景转场的名字，`transitionDuration` 默认 0.4 秒；非硬切的镜头转场会自动配一声轻的 whoosh。
- 不用 `shots()` 的场景和以前完全一样；两种写法可以在一部片子里混用。

## 镜头运动

写在 `cam` 或 `CAMS` 里，都返回 `{ x, y, z }`，可以互相嵌套：

| 函数 | 说明 |
|---|---|
| `camFit(x0, y0, x1, y1, pad=0.08)` | 让场景里的一个矩形撑满画面，用来给特写：人脸、手、一件道具 |
| `camMove(a, b, p, ease=easeInOut)` | 从取景 a 运动到取景 b（推近、拉远、平移）；p 常用 `sh.p`。缩放按等比速度走，不会前快后慢 |
| `camDrift(cam, t, amount=10)` | 给一个取景加上缓慢的手持漂移，停着的画面也不会僵住 |
| `punchIn(lt, at, amount)`、`shake(lt, at, amp, dur)` | 冲击瞬间的一下推近、震屏（见 motion.md） |

```js
cam: (lt, S, sh) => camDrift(camMove(camFit(140, 300, 760, 1100), { x: 540, y: 960, z: 1 }, sh.p, easeOut), lt, 8),  // 从钟的特写拉开到全景，带一点漂移
```

推近以后，画面四周的内容会被推出画框，所以布景要画得比画布大（见下一节）。

## 景深：`layer(depth, fn)`

镜头一动，远近不同的东西应该动得不一样。`layer` 让 `fn` 里画的内容按另一个深度跟随当前镜头：

- `1`：和场景主体一起动（不写 `layer` 就是 1）
- 小于 1：更远，动得少、缩放得少（远山、天空、墙上的窗）
- 大于 1：比主体更近，动得更多（前景的柱子、探进画面的人、垂下来的钟沿）
- `layer(0, fn)`：固定在屏幕上

```js
layer(0.4, () => nightSky(t));                       // 远景
palaceGate(540, 1500, 1.25, 0);                      // 主体
layer(1.5, () => drawPillars());                     // 前景，推近时向两边滑出去
```

## 画满整屏

`SAFE` 是**字**的安全区：标题、字幕和平台界面不会挡到里面的文字。画面不受它限制，布景可以铺满整个画布。镜头会动的时候，四周多画出几百像素（比如从 `-600` 画到 `W + 600`），平移、推近时才不会露出边。画面显得空的时候，先看看是不是把所有内容都收进了一个居中的小框。

竖屏下方 75% 高度以下是字幕的位置，那里放背景和人物的下半身没问题，不要放需要读的字。

## 光影和调色（在一幕或一个镜头的最后调用）

| 函数 | 说明 |
|---|---|
| `lightPool(x, y, r, color, alpha)` | 在已经画好的画面上叠一团光（灯、窗、月亮）；场景坐标 |
| `grade(color, alpha, mode='multiply')` | 整个画面染一层色调：`multiply` 压向某种气氛，`screen` 提亮 |
| `vignette(strength, color, inner)` | 四周压暗，把视线收到中间 |
| `flash(p, color, peak)` | 冲击瞬间的全屏一闪，p 从 0 到 1 是整个过程 |

这些都很便宜。不要在每一帧里用 `ctx.filter = 'blur(…)'`，它在截图用的 CPU 画布上极慢；需要柔边的东西用 `sprite()` 预先画成贴图（见 primitives.md）。

光影是加分项，不能代替画面本身：一片黑加一束光并不比一张画得清楚的画更好看，也更容易把片子做得阴森。

## 声音的起伏

- 重音效：`boom`（低沉的撞击）、`drum`（一声大鼓）、`gong`（大钟，余音 4 秒），配合镜头切换和冲击画面用。
- 场景的 `musicLevel`（script.json）：这一幕的配乐音量倍数，1 是正常，0 是静音，大于 1 更响；场景交界处自动过渡。紧张的段落抬高，独白的段落压低，整片就有了起伏。

## 写代码之前：分镜表

先把每句台词要给观众看什么列出来，再写 `scenes.js`。写在哪里都行（注释、一张表、对话里），内容完全由你定。列的时候问自己：

- 这句话说的时候，观众看到的是什么？和上一个画面有什么不一样？
- 这个画面里什么在动？是人物、道具、文字，还是镜头？
- 这一句适合全景、中景，还是某个东西的特写？
- 整片最有分量的三五个画面是哪几个？开头三秒放的是不是其中之一？
- 用户已经认可了画风和人物时：我换的只是镜头做法，还是把他认可的东西也换掉了？

## 看片自查：`snap.mjs` 的节奏报告

`node scripts/snap.mjs` 每次都会打印一段 `pacing`，并把每个镜头的数字写进 `snaps/pacing.txt`：

```
pacing: 15 shots in 33s, average 2.2s, longest 4.1s (end)
  frame use 98% on average; 19% of the picture changes every half second; 15 of 15 shots have their own camera move
```

- `holds`：这个镜头停多久。
- `frame use`：这个镜头自己画的内容占整个画面的比例（和一张空场景比出来的）。
- `moving/0.5s`：字幕以上的画面里，和半秒前不一样的部分占多少。
- `camera`：镜头自己写了运动，还是默认推近；缩放了多少、移动了多少。

这些是观察，不是及格线，没有“应该是多少”，脚本也不会因为它们失败。同一段内容的两种做法可以拿来对比：一段 31 秒的戏，五个场景各一个构图时是“平均 6.3 秒一个镜头，画面占 43%，每半秒 4% 在变”；拆成 15 个镜头、铺满画面以后是“2.2 秒，98%，19%”。

`node scripts/snap.mjs --strip` 每个镜头出一行连续帧（竖屏 4 张、横屏 3 张），用来看一个镜头里到底动了没有；加 `--scene bell,last` 只看某几幕。这个模式只写总览图。

看的时候问自己：

- 哪个镜头停得最久？那几秒里观众在看什么变化？
- 画面有没有用满？哪几个镜头只占了中间一块？
- 连着看几行，是不是每一行的构图都差不多（同样的站位、同样的景别）？
- 关掉声音看，能不能看出哪里是高潮？
