# 踩过的坑

## 渲染
- **画面必须是 t 的纯函数。** 不能用 `Math.random()`，不能在帧之间累积变量，不能依赖 `requestAnimationFrame` 的次数。否则逐帧导出的结果和预览不一致，转场时“冻结上一帧”也会出错。
- **缓动函数在 0 处的浮点误差。** 原始的 easeOutBack(0) 算出来约等于 1e-16，`if (x > 0)` 会提前成立，比如答案节点在推理开始前就变绿了。引擎里的版本已经修正；自己写的缓动也要处理 t≤0 的情况。
- **file:// 下不能加载 ES 模块，也不能 fetch。** 所以引擎是普通脚本加全局函数，时间轴写成 `timeline.js`（`window.TIMELINE = …`），不是 json 文件。
- **字体要先加载完。** 引擎的 `window.ready` 会等所有风格用到的字体加载完再画第一帧。导出和截图脚本都已经等待它，自己写工具时也要等。
- **ctx 不要缓存。** 淡入淡出转场会把全局 `ctx` 临时换成离屏画布，场景里请直接用 `ctx`。
- **只用 `ctx.stroke()` 描边的线条不会跟风格变。** 自己画的路径请用 `strokeInk()`。但背景里那种密集的细线（排线、网格）直接用 `ctx.stroke()`，这样更快，也更干净。

## 版面和可读性
- **标题会被镜头裁掉。** 标题、进度条这些 HUD 类元素要用 `pinned()` 包起来（`drawTag`、`drawProgress` 已经内置）。
- **标签挤在一起。** 相邻弧线的权重数字放在弧顶会互相重叠，改放到方块下方。编号类小字要控制在 4 位以内、19px 左右。
- **重要内容被遮挡。** 叉号盖住了“7”，气泡尾巴位置不对导致画出一条怪线。弹出的标记要放在内容旁边；气泡尾巴的目标点要在气泡底边以下。
- **深色风格下的高亮。** 实心高亮底上的文字用 `C.onMark`；半透明高亮在深色背景上不透明度要降到 0.35 左右，否则会盖住浅色文字。
- **颗粒太重。** 颗粒强度超过 30 左右时，整个画面会发灰。暗角在浅色风格下不要超过 0.15。

## 风格相关
- **像素风格下文字会变糊。** pixelate 3 时，40px 的字只剩 13 个像素点高。关键文字至少用 40px，编号类小字在像素风格下基本看不清。
- **毛笔线条很慢。** 每一笔都要做一次模糊，线条多的场景在水墨风格下导出会明显变慢。
- **等轴测的遮挡要自己排序。** 画错顺序会出现后面的方块压住前面的方块。
- **剪纸的“滑入”转场。** 新场景是整张滑上来的，固定在屏幕上的标题在滑入过程中会被裁掉一部分，这是正常现象。

## 画面比例
- 场景坐标要用 `W`、`H`、`SAFE` 来算，写死 1920、1080 就只能在横屏下使用（`llm-reasoning` 和 `iso-city` 两个示例就是只适配横屏的写法）。
- 竖屏的空间主要在纵向：一行放 2 到 3 个元素，主体上下排列；字幕在 84% 高度附近，角色和地面线放在 `SAFE.y1` 附近。

## 镜头
- 推近时，画面四周的内容会被推到屏幕边缘，可能压到左上角的标题和右上角的章节标签。推近幅度一般不超过 1.15，推近时主体要放在画面中间。

## 回归测试
- 截图时页面会带上 `?snap=1`，主画布改用 CPU 渲染（`willReadFrequently`），这样同一帧反复渲染的结果完全一致。以前用 GPU 渲染时，截图帧数一多，会偶尔出现 1 个像素值的差异，被误报成“不是纯函数”。
- 缩略图画布必须用 `willReadFrequently: true`：Chrome 的 canvas 在第一次 `getImageData` 之后会从 GPU 切换到 CPU，两条路径缩放出来的像素略有不同，会让基准图对比出现误报。
- 画面变化是有意的，就运行 `selftest.mjs --update-golden`，并在提交说明里写清楚。

## 配音和时间轴
- **edge-tts 的逐词时间戳比 mp3 音频早约 0.09 秒**（编码器延迟），tts.mjs 已经用 `LAG` 补偿。换 TTS 引擎时要重新测量这个值。
- **每句话首尾加了淡入淡出**（0.04 秒 / 0.015 秒），否则裁掉静音后的第一个采样可能不在零点，会有“咔哒”声。整条音轨用 loudnorm 统一到 -16 LUFS 左右。
- **edge-tts 偶尔连接超时。** 脚本会重试 3 次，并按“声音 + 语速 + 文本”缓存，重跑时只合成改动过的句子。
- **首尾静音。** TTS 输出的音频前后有静音，会让字幕和画面提前。脚本已经用 silenceremove 裁掉。
- **换声音会改变时长。** 原来的 Tingting 是 79 秒，换成云希后是 63 秒。所以动作时间要挂在 `S.L(i)` 上，并且在 `hold` 里给收尾动画留出时间。
- **写画面时先用 `--dry`。** 估算的时长和真实配音不一样，换成真实配音后要重新截图检查一遍。

## 导出
- 导出的方式：多个 Chrome 并行，每个负责一段帧，在页面里用 WebCodecs 编成 H.264，最后按字节拼接再混入配音。实测 63 秒的视频从 197 秒（逐帧 PNG）降到 13 秒。
- 旧的瓶颈是 PNG 编码加传输，每帧 97 ms，而画一帧只要 1–25 ms。所以不要再回到“截 PNG 喂给 ffmpeg”的做法。
- 新旧版成片的 PSNR 大约 38 dB，差别集中在颗粒噪点上，肉眼看不出。想要更高画质用 `--bitrate 30`。
- 画一帧的耗时（M4）：paper / chalk / pixel 约 1 ms，blueprint / neon 约 9 ms，ink 约 26 ms（每一笔都有模糊）。
- `--draft` 是 15fps、4 Mbps，只用于预览，不要当成片交付。
- 导出、截图、混音都要启动 Chrome：会自动查找各平台的常见位置，找不到时用 `CHROME_PATH` 指定。
- **在 Codex 等带沙箱的 agent 里，Chrome 通常起不来**（`Failed to launch the browser process`）。snap、mix、export 需要在沙箱外运行（批准提权，或者用可以访问浏览器的沙箱模式）；init 和 tts 需要联网。
- 导出前要先有 `voice.wav`；用 `--dry` 生成的是静音音轨。
